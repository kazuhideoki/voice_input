# ADR-0002: リアルタイム文字起こしに GPT Live Transcribe を採用する

- Status: Accepted
- Date: 2026-07-31
- Supersedes: ADR-0001 のリアルタイム文字起こしモデルに関する決定

## 背景

ADR-0001 では、録音中のリアルタイム文字起こしに `gpt-realtime-whisper` を使い、
`gpt-live-transcribe` の採否を別の判断として残した。

OpenAI は、継続的なライブ音声の低遅延文字起こし向けモデルとして
`gpt-live-transcribe` を公開し、`gpt-realtime-whisper` からの移行先として案内している。
既存の Realtime transcription session、WebSocket、音声送信イベント、転写イベントは
維持できる一方、言語指定は単一の `language` から `languages` 配列へ変わる。

このアプリケーションは日本語の音声入力を目的とし、録音中の部分転写を直接入力して、
停止後の確定転写で内容を補正する。リアルタイム経路では単一の録音を手動で確定しており、
複数ターンの自動検出、話者ラベル、単語単位の時刻、信頼度は必要としていない。

## 決定

録音中のリアルタイム文字起こしを `gpt-live-transcribe` へ置き換える。

- 公開する provider 名は `gpt-live-transcribe` とし、旧 `realtime-whisper` は受理しない。
- モデルは `gpt-live-transcribe`、期待言語は日本語に固定する。
- 低遅延と確定精度の両方を考慮した開始点として、転写の delay は `low` に固定する。
- 自動ターン検出は利用せず、録音停止時の手動 commit を維持する。
- prompt、keywords、複数言語、話者ラベル、時刻、信頼度を新しい設定項目として追加しない。
- WebSocket 接続、24 kHz PCM 入力、部分転写と確定転写の処理は維持する。

## 判断理由

### 採用した構成

`gpt-live-transcribe` は継続的なライブ音声の推奨モデルであり、既存の通信方式と転写
イベントを維持したまま移行できる。モデル名だけでなく言語指定も新しい契約へ合わせる
ことで、廃止されたフィールドに依存しない構成になる。

delay の `low` は、OpenAI が低遅延のライブ表示に対する開始点として案内している。
`minimal` はさらに早い部分転写を得られる一方で精度とのトレードオフがあるため、
発話中の直接入力だけでなく停止後の確定結果も利用するこのアプリケーションでは `low` を
初期値とする。この選択は実音声での確認前の暫定値であり、部分転写と確定結果に差がある
場合は現在の補正処理で扱う。

手動 commit を維持すれば、一回の録音を一つの転写項目として処理できる。自動ターン検出を
同時に採用すると、複数項目の識別と完了順序を扱う責務が増えるため、モデル置換には
含めない。

### 比較した選択肢

#### `gpt-realtime-whisper` を維持する

変更は不要だが、OpenAI が新しいライブ文字起こしの開始点として案内するモデルへ移行
できず、新しい言語指定と遅延調整を利用できないため採用しない。

#### provider 名だけを `realtime-whisper` のまま維持する

呼び出し側の変更は減るが、公開名と実際のモデルが一致しなくなる。個人利用で破壊的変更を
許容し、旧名の互換エイリアスを持たない既存方針とも一致しないため採用しない。

#### 自動ターン検出と文脈指定も同時に追加する

モデルが提供する機能を広く利用できる一方、複数ターンの順序制御、設定の入力経路、
入力値検証が新たに必要になる。自動ターン検出は現在の単一録音による音声入力には必須で
ない。prompt と keywords は、ADR-0001 で採用した任意 prompt を公開せず辞書による
後処理を行う方針を継承するため追加しない。固定的な固有語を辞書で十分に補正できないことが
確認された場合は、文脈指定の採用を別の判断として扱う。

## 結果

### 得られる効果

- ライブ音声向けの推奨モデルと公開 provider 名が一致する。
- 既存の録音、通信、部分入力、確定補正の構造を維持できる。
- 新しい API 契約に沿った日本語指定と遅延設定を利用できる。

### 受け入れる不利益

- `realtime-whisper` を指定する既存の CLI、IPC、環境設定はエラーになる。
- delay を変える実行時設定は提供しない。
- prompt、keywords、複数言語、自動ターン検出は利用できない。
- 実音声での認識品質と体感遅延は、モデル移行後に改めて確認する必要がある。

### 実音声での受け入れ条件

代表的な日本語発話を実際のマイクと利用環境で入力し、次を満たすことを確認する。

- 発話中に空でない部分転写を受信し、録音停止後に空でない確定転写を受信できる。
- 確定転写が既存の 30 秒の待機時間内に完了し、重複や欠落なく入力内容を補正できる。
- 体感遅延と認識品質が、日常の音声入力を継続できる範囲に収まる。

部分転写が実用にならない、確定転写が待機時間を超える、または認識品質が継続利用に
耐えない場合は本決定を再検討し、代表音声を使って `minimal`、`low`、`medium` を比較する。
